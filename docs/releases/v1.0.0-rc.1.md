# Blossom v1.0.0-rc.1

Release candidate. This is not stable `v1.0.0`.

The image workflow publishes `1.0.0-rc.1` and an immutable `sha-` tag. It does not move `latest`,
`1`, or `1.0` for this prerelease. The live Blossom service is not deployed by the tag.

`v1.0.0-beta.1` stays where it is. There is no GitHub Release named `v1.0.0`.

Self-hosting SmartFlowSocial does not require this service. The internal publisher and reader ship
in the main application.

The published image is `ghcr.io/smartflowsocial/smartflowsocial-blossom:1.0.0-rc.1` at
`sha256:0c7971b01c480b244cd62bd944849fa1a1d837e7ecbbf4e9ddfdacac8a4b07f2`. The tag source is
`125e4c7b067a8e95bcafb66654139e7c7dd9bf61`.

The Release Security run on that tag,
[44800470625](https://github.com/smartflowsocial/smartflowsocial-blossom/actions/runs/44800470625),
built the image and passed Trivy. SBOM generation finished, then `anchore/sbom-action` failed with
`Resource not accessible by integration` while attaching the file to the GitHub Release. The
workflow only has `contents: read`. That run stays as the historical record. The default-branch
workflow sets `upload-release-assets: false` and uploads the SBOM as an Actions artifact. Dispatch
it with `candidate_sha` and `image_digest` to pull this image and scan it again. That dispatch does
not push an image and does not move the tag. `ignore-unfixed: true` still fails a HIGH or CRITICAL
finding that has a fix. Debian findings without a fixed version, including CVE-2023-45853, stay
outside that gate. Passing the gate does not mean the image has zero vulnerabilities.
